# 2. VOTER VERIFICATION MODULE

## Purpose

Before voting, the system must verify that:

1. The user is authenticated.
2. The user is eligible for the selected election.
3. Required verification is completed.
4. The voter has not already voted.
5. The voter receives one-time voting authorization.

---

# Voter Eligibility Validation

When a voter enters an election:

Backend must verify:

* User exists
* User account is valid
* Election exists
* Election is currently active
* User is eligible for the election
* User has not already voted
* Election rules allow voting

If any validation fails, voting must not continue.

---

# Email OTP Verification

If the election requires OTP:

Create a voter verification flow.

Flow:

Authenticated User
↓
Select Election
↓
Eligibility Check
↓
Request OTP
↓
Send OTP
↓
Enter OTP
↓
Verify OTP
↓
Verification Success
↓
Continue

OTP requirements:

* Cryptographically secure 6-digit OTP
* Expiry time
* Maximum attempts
* Resend cooldown
* Rate limiting
* OTP must never be stored as plaintext
* OTP must never appear in logs
* OTP must never be returned by API

Reuse the existing OTP infrastructure where possible instead of creating a duplicate authentication OTP system.

---

# Webcam / Face Verification

If enabled for the election:

Create a voter-facing webcam verification page.

Requirements:

* Request camera permission
* Show live webcam preview
* Capture required frames
* Detect face
* Validate face quality
* Compare with the registered voter identity
* Return verification result
* Handle camera denial
* Handle no-face detection
* Handle multiple-face detection
* Handle poor-quality image
* Handle verification failure

Use:

* OpenCV
* Face Recognition / ArcFace as appropriate

Do not create a separate biometric enrollment UI unless absolutely required by the existing backend design.

Biometric configuration should remain election/backend controlled.

---

# One-Time Voting Authorization

After successful eligibility + required verification:

Generate a secure one-time voting authorization.

Authorization must:

* Be tied to user
* Be tied to election
* Expire
* Be single-use
* Cannot be reused
* Cannot be transferred to another election
* Cannot be used after election ends

Example flow:

AUTHENTICATED
↓
ELIGIBILITY VALIDATED
↓
OTP VERIFIED (if enabled)
↓
FACE VERIFIED (if enabled)
↓
VOTING AUTHORIZATION GENERATED
↓
VOTING PAGE UNLOCKED

Do not allow frontend-only authorization.

Backend must validate authorization before accepting a vote.

Create a clear voter verification progress interface:

✓ Authentication
✓ Election Eligibility

✓ Voting Authorization

---

# Secure Vote Submission

When voter confirms:

Frontend → Backend API

Backend must atomically:

1. Validate authenticated user
2. Validate election
3. Validate election status
4. Validate voter eligibility
5. Validate voting authorization
6. Validate candidate
7. Check voter has not already voted
8. Store vote
9. Mark voting authorization as consumed
10. Mark voter as voted for that election
11. Record audit event
12. Return success

Prevent duplicate submissions caused by:

* Double clicking
* Refresh
* Multiple browser tabs
* API replay
* Concurrent requests

Use database transactions and appropriate constraints/locking.

---

CRITICAL SECURITY RULE:

Enforce this at database/backend level.

Frontend.

Create a database constraint/model design that prevents duplicate votes.

Design the database so voter identity and vote choice are separated as much as practical while still supporting one-vote enforcement and auditability.
